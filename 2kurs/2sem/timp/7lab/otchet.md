## 5. Описание классов

### 5.1 `BaseAI` (абстрактный класс)

**Назначение:** базовый класс для «интеллектуального поведения» объектов. Создаёт и управляет потоком.

**Ключевые поля:**

| Поле | Тип | Описание |
|------|-----|----------|
| `employees` | `List<? extends Employee>` | Список объектов для управления |
| `aiThread` | `Thread` | Поток, в котором выполняется расчёт движения |
| `running` | `volatile boolean` | Флаг работы потока |
| `paused` | `volatile boolean` | Флаг паузы (засыпание через wait) |
| `pauseLock` | `Object` | Объект синхронизации для `wait()`/`notifyAll()` |
| `velocity` | `double` | Скорость движения (пикселей/сек) |

**Ключевые методы:**

- `start()` — создаёт и запускает поток `aiThread` с методом `runLoop()`. Поток daemon, завершится вместе с приложением.
- `stop()` — выставляет `running = false`, вызывает `notifyAll()` для пробуждения из `wait()`, ожидает завершения потока через `join()`.
- `pause()` — выставляет `paused = true`. Поток в следующем цикле заходит в `synchronized(pauseLock)` и вызывает `wait()`, засыпая до пробуждения.
- `resume()` — внутри `synchronized(pauseLock)` выставляет `paused = false` и вызывает `notifyAll()`, пробуждая поток.
- `setThreadPriority(int)` — устанавливает приоритет потока (1–10).
- `runLoop()` — основной цикл потока: проверка паузы → обновление позиций → `Thread.sleep(16)` (~60 FPS).

### 5.2 `DeveloperAI` (наследует `BaseAI`)

**Назначение:** хаотичное движение разработчиков со случайной сменой направления.

**Ключевые поля:**

| Поле | Тип | Описание |
|------|-----|----------|
| `directionChangeInterval` | `int` | Интервал смены направления (в секундах) |
| `employeeAngles` | `Map<Employee, Double>` | Карта: разработчик → свой угол направления (радианы) |
| `lastChangeTimes` | `Map<Employee, Long>` | Карта: разработчик → время последней смены направления (мс) |

**Логика `updatePositions()`:**

1. Для каждого разработчика проверяется: есть ли у него уже угол? Если нет — инициализируется случайным значением (`0…2π`).
2. Проверяется, прошло ли `N` секунд с последней смены направления. Если да — угол случайно меняется.
3. Вычисляется смещение: `dx = cos(angle) * velocity * deltaTime`, `dy = sin(angle) * velocity * deltaTime`.
4. Позиция обновляется. При столкновении с границей — угол отражается + добавляется случайное отклонение для хаотичности.

**Почему каждый разработчик двигается индивидуально:**

У каждого разработчика **свой** угол в `employeeAngles` и **своё** время последней смены в `lastChangeTimes`. Когда поток `DeveloperAI` бежит по списку, он считывает угол конкретного разработчика, вычисляет его смещение и обновляет его позицию. При смене направления — только у этого конкретного разработчика меняется угол.

### 5.3 `ManagerAI` (наследует `BaseAI`)

**Назначение:** движение менеджеров по окружности.

**Ключевые поля:**

| Поле | Тип | Описание |
|------|-----|----------|
| `orbitRadius` | `double` | Радиус орбиты |
| `employeeAngles` | `Map<Employee, Double>` | Карта: менеджер → текущий угол на орбите |
| `orbitCenters` | `Map<Employee, double[]>` | Карта: менеджер → центр орбиты `[x, y]` |

**Логика `updatePositions()`:**

1. Если менеджер новый (нет в `orbitCenters`) — вызывается `initManager()`: назначается случайный центр орбиты и начальный угол.
2. Угловая скорость: `ω = V / R` (рад/сек). За кадр (`δt = 0.016 сек`) угол увеличивается на `δφ = ω * δt`.
3. Позиция вычисляется по формуле окружности:
   - `x = centerX + R * cos(angle)`
   - `y = centerY + R * sin(angle)`
4. Если орбита выходит за границы мира — центр орбиты пересчитывается.

## 6. Многопоточность и синхронизация

### 6.1 Как работает пауза через `wait()` / `notifyAll()`

```java
// В BaseAI.runLoop():
while (running) {
    synchronized (pauseLock) {
        while (paused && running) {
            pauseLock.wait();  // Поток засыпает, освобождая монитор
        }
    }
    // ... обновление позиций ...
    Thread.sleep(16);
}
```

- `pause()` → выставляет `paused = true`. На следующей итерации цикл заходит в `synchronized` блок и вызывает `wait()` — поток **засыпает**, не потребляя CPU.
- `resume()` → внутри `synchronized(pauseLock)` выставляет `paused = false` и вызывает `notifyAll()` — поток **пробуждается** и продолжает выполнение.

### 6.2 Синхронизация потоков

| Конфликт | Решение |
|----------|---------|
| AI-поток пишет позицию, основной поток читает для рисования | `synchronized(employees)` в `updatePositions()`. Рисование читает копию списка (`habitat.getEmployees()`), объекты immutable по позиции за один кадр |
| Основной поток добавляет объект в коллекцию AI | `synchronized(ai.employees)` — добавление в список защищено |
| AI-поток удаляет истёкшие объекты | Удаление происходит в основном потоке (`Habitat.update()`), AI только читает список |

### 6.3 Приоритеты потоков

Приоритеты устанавливаются через `Thread.setPriority()`:

| Значение | Константа | Описание |
|----------|-----------|----------|
| 1 | `Thread.MIN_PRIORITY` | Минимальный приоритет |
| 5 | `Thread.NORM_PRIORITY` | Стандартный (по умолчанию) |
| 10 | `Thread.MAX_PRIORITY` | Максимальный приоритет |

Планировщик ОС (Linux/Windows) использует приоритеты для распределения CPU-времени. Однако на современных ОС приоритеты Java-потоков — это **подсказки**, а не жёсткие гарантии.

## 8. Ответы на возможные вопросы к защите

### Что такое `volatile` и зачем оно нужно?

`volatile` гарантирует, что значение поля всегда читается из основной памяти, а не из кэша потока. Без `volatile` один поток может не увидеть изменение флага `running` или `paused`, сделанного другим потоком.

### Почему рисование должно быть в основном потоке?

JavaFX не является потокобезопасным. Все операции с UI-элементами (Canvas, Label и т.д.) должны выполняться **только** в JavaFX Application Thread. Попытка рисования из другого потока приведёт к исключениям или неопределённому поведению.

### Чем `wait()/notify()` отличается от `Thread.sleep()`?

- `sleep()` — поток засыпает на фиксированное время, не освобождает мониторы.
- `wait()` — поток засыпает **навсегда** (или до `notify()`), **освобождает монитор**. Потребляет 0 CPU во время ожидания.

### Что такое `synchronized` и зачем он здесь?

`synchronized` обеспечивает взаимное исключение: только один поток может войти в `synchronized`-блок для данного объекта-монитора. Здесь он защищает:
- Список `employees` от одновременного чтения (AI-поток) и записи (Habitat).
- Флаг `paused` от гонок данных (data race).

### Как работает формула движения по окружности?

Угловая скорость: `ω = V / R` (рад/сек). За время `Δt` угол увеличивается: `φ_new = φ_old + ω * Δt`.
Позиция на окружности:
- `x = centerX + R * cos(φ)`
- `y = centerY + R * sin(φ)`
