## 1. Цель работы

Целью данной лабораторной работы является программирование дерева порождающих процессов с использованием данных в общей разделяемой памяти. Процессы совместно реализуют рекурсивный алгоритм сортировки массива. Для синхронизации используются семафоры.

## 2. Постановка задачи

Реализовать программу, которая:
- Создает дерево процессов заданной глубины
- Использует разделяемую память для хранения массива данных
- Применяет семафоры для синхронизации завершения процессов-потомков
- Выполняет сортировку массива рекурсивным разделением (алгоритм 72-01)
- Собирает статистику времени выполнения и количества созданных процессов

## 3. Теоретическая часть

### 3.1 Разделяемая память в POSIX

Разделяемая память (shared memory) позволяет нескольким процессам обращаться к одной области памяти. Это наиболее эффективный способ обмена данными между процессами, так как не требует системных вызовов для передачи данных.

Основные функции для работы с разделяемой памятью:
- `shm_open()` - создание или открытие объекта разделяемой памяти
- `ftruncate()` - установка размера
- `mmap()` - отображение памяти в адресное пространство процесса

### 3.2 Семафоры

Семафоры используются для синхронизации доступа к разделяемым ресурсам. В данной работе они применяются для ожидания завершения процессов-потомков.

Основные функции:
- `sem_open()` - создание или открытие семафора
- `sem_wait()` - ожидание семафора (P-операция)
- `sem_post()` - сигнал о завершении (V-операция)
- `sem_close()` - закрытие семафора
- `sem_unlink()` - удаление семафора

### 3.3 Процессы

Процессы создаются с помощью системного вызова `fork()`. Дочерний процесс получает копию адресного пространства родителя, включая отображенную разделяемую память.

## 4. Описание алгоритма сортировки

### 4.1 Алгоритм 72-01 (рекурсивное разделение)

Алгоритм основан на принципе "разделяй и властвуй":
1. Массив делится на две примерно равные части
2. Каждая часть сортируется независимо
3. Затем выполняется слияние двух отсортированных половин

В отличие от классической сортировки слиянием, в алгоритме 72-01:
- Разделение происходит всегда пополам
- Слияние выполняется после сортировки обеих половин
- Для небольших подмассивов используется сортировка вставками

### 4.2 Сортировка вставками

Для локальной сортировки небольших подмассивов используется алгоритм сортировки вставками (insertion sort) со сложностью O(n²). Он эффективен для малых размеров массива.

## 5. Структура программы

### 5.1 Основные структуры данных

```c
// Структура для параметров задачи потомка
typedef struct {
    int left;             // Левая граница интервала
    int right;            // Правая граница интервала
    int depth;            // Текущая глубина рекурсии
    int child_sem_index;  // Индекс семафора для оповещения родителя
    pid_t child_pid;      // PID потомка
} TaskParams;

// Структура разделяемой памяти
typedef struct {
    int *array;           // Указатель на массив данных
    int size;             // Размер массива
    int max_depth;        // Максимальная глубина рекурсии
    sem_t *semaphores;    // Массив семафоров
    TaskParams *tasks;    // Параметры задач
    int process_count;    // Счетчик созданных процессов
    int sem_count;        // Количество семафоров
} SharedMemory;
```

### 5.2 Основные функции

1. **`process_sort()`** - рекурсивная функция сортировки с созданием процессов
2. **`local_sort()`** - локальная сортировка вставками
3. **`merge()`** - слияние двух отсортированных половин
4. **`init_shared_memory()`** - инициализация разделяемой памяти
5. **`check_sort_result()`** - проверка корректности сортировки
6. **`verify_with_qsort()`** - сравнение с эталонной сортировкой qsort
7. **`cleanup_shared_memory()`** - очистка ресурсов

### 5.3 Логика работы рекурсивной сортировки

1. Проверка базовых условий (пустой массив или один элемент)
2. Проверка необходимости локальной сортировки (глубина >= max_depth или размер < THRESHOLD)
3. Разделение массива на две части
4. Создание двух семафоров для синхронизации потомков
5. Создание первого потомка через fork()
6. Создание второго потомка через fork()
7. Ожидание завершения обоих потомков через семафоры
8. Слияние отсортированных половин
9. Сигнализация родительскому процессу о завершении

## 6. Реализация синхронизации

### 6.1 Схема синхронизации

```
Родительский процесс P
    ├── Создает семафоры sem1 и sem2 (начальное значение 0)
    ├── Создает потомка P1 (сортирует левую половину)
    ├── Создает потомка P2 (сортирует правую половину)
    ├── Выполняет sem_wait(sem1) - ожидание P1
    ├── Выполняет sem_wait(sem2) - ожидание P2
    └── После завершения обоих потомков выполняет слияние

Потомок P1
    ├── Выполняет сортировку
    └── Выполняет sem_post(sem1) - сигнал родителю

Потомок P2
    ├── Выполняет сортировку
    └── Выполняет sem_post(sem2) - сигнал родителю
```

### 6.2 Именование семафоров

Для уникальности имена семафоров формируются на основе PID родительского процесса:
```c
snprintf(sem_name, sizeof(sem_name), "/sem_lab1_v15_%d_%d", getpid(), index);
```

## 9. Особенности реализации

### 9.1 Учет особенностей WSL
Вместо функции `clock()` из `time.h` используется `clock_gettime(CLOCK_MONOTONIC)`, которая корректно работает в WSL с многопоточными/многопроцессными программами.

### 9.2 Обработка ошибок
- Проверка возвращаемых значений всех системных вызовов
- Корректное освобождение ресурсов при ошибках
- Обработка сигналов для очистки разделяемой памяти при прерывании программы

### 9.3 Избегание зомби-процессов
После завершения потомков родитель выполняет `waitpid()` для сбора статуса завершения.

### 9.4 Атомарные операции
Для увеличения счетчика процессов используется атомарная операция `__atomic_add_fetch()`.
