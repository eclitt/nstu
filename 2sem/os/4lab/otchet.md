# ОТЧЁТ  
## Лабораторная работа: рекурсивная сортировка с обменом данными по TCP (localhost)

---

## ВВЕДЕНИЕ

В рамках работы исходная постановка лабораторной №1 (рекурсивное разделение массива и слияние отсортированных частей с использованием нескольких процессов) перенесена с механизма разделяемой памяти и семафоров на сетевой взаимодействие в пределах одной машины. В качестве транспорта используются потоковые сокеты TCP; адрес привязки — `127.0.0.1` (localhost). Предпочтительный номер порта сервера задаётся по идентификатору процесса (младшие 16 бит PID), что соответствует духу технического задания из `tz.txt`. Если этот порт уже занят (`EADDRINUSE`), выполняется перебор следующих портов по кругу в пределах ограниченного числа попыток; фактический порт передаётся потомкам через переменную окружения, чтобы они подключались к правильному адресу.

---

## ЦЕЛЬ РАБОТЫ

Освоить организацию межпроцессного обмена через сокеты в модели «родитель — потомок»: корневой и промежуточные процессы выступают серверами на `127.0.0.1` с приоритетным портом по PID и при необходимости — запасными портами; потомки узнают номер порта родителя из окружения (или из PID при отсутствии переменной), получают фрагмент массива, выполняют рекурсивное ветвление или локальную сортировку и возвращают результат в формате, заданном в ТЗ.

---

## ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ

**Процессы и `fork`.** Родительский процесс создаёт копии себя вызовом `fork()`. Потомок получает собственный PID и PID родителя (`getppid()`). Номер порта для `connect` задаётся через наследуемую переменную окружения с фактическим портом после `bind`, что устраняет рассогласование, когда занят «идеальный» порт по PID и выбран запасной.

**Сокеты TCP.** Пара `socket` → `bind` → `listen` переводит процесс в режим ожидания входящих соединений на выбранном интерфейсе и порту. Клиент выполняет `connect` к тому же адресу и порту. Ошибка `EADDRINUSE` при `bind` означает, что порт уже используется другим сокетом или недавно был в состоянии, мешающем повторной привязке; в учебной программе при только этой ошибке выполняется попытка привязки к следующему порту. Для надёжной передачи фиксированного объёма данных используют циклы `read`/`write`.

**Переменные окружения.** Вызов `setenv` перед `fork` задаёт строковое значение, копируемое в адресное пространство потомка; так передаётся выбранный порт без изменения протокола обмена массивом по TCP.

**Сортировка слиянием по процессам.** Массив делится на две части; каждая сортируется (рекурсивно или локально при достижении предела глубины), после чего отсортированные части сливаются в один отрезок. Локальная сортировка реализована методом вставок; в ответе потомка передаётся счётчик сдвигов элементов при вставках как показатель «обменов» в смысле перемещений данных в массиве.

**Порт и PID.** Предпочтительный порт — младшие 16 бит PID (`PID & 0xFFFF`). При коллизии с уже занятым портом перебираются последующие значения (до лимита попыток), с уведомлением в стандартный поток ошибок.

## ОПИСАНИЕ АЛГОРИТМА

1. **Корневой процесс** задаёт массив случайных чисел, параметр максимальной глубины рекурсии `max_depth` и вызывает сортировку всего массива при глубине 0 (логически: потомкам передаётся «глубина рекурсии + 1», то есть 1).

2. **Родитель на очередном уровне** вызывает привязку к `127.0.0.1`, начиная с порта `pid_to_port(getpid())`, при `EADDRINUSE` увеличивая номер порта до успешного `bind`. Затем записывает выбранный порт в переменную окружения `LAB1_SRV_PORT` и порождает потомков. Потомок подключается к `127.0.0.1` и порту из `LAB1_SRV_PORT` (если переменная задана корректно), иначе использует `pid_to_port(getppid())`, и ожидает задание по соединению.

3. Родитель принимает соединение (`accept`), отправляет потомку сообщение: **глубина рекурсии + 1** (32-битное целое), **размер подмассива** `n`, затем `n` элементов массива (32-битные целые, порядок байт сети не используется — локальный хост, `int32_t`).

4. Аналогично порождается и обслуживается второй потомок для правой половины.

5. **Потомок**, получив данные, сравнивает принятую глубину с `max_depth`:
   - если достигнут предел — выполняется локальная сортировка вставками, подсчитывается число сдвигов при вставке;
   - иначе потомок сам поднимает сервер на `127.0.0.1` с тем же правилом «PID-порт и запасные», обновляет `LAB1_SRV_PORT`, снова создаёт двух потомков и повторяет протокол до получения от них отсортированных половин, затем сливает их.

6. **Ответ потомка родителю:** **счётчик обменов (сдвигов)**, **размер `n`**, **отсортированный массив из `n` элементов**.

7. Родитель читает оба ответа, выполняет слияние двух отсортированных половин в исходный отрезок и при необходимости передаёт результат вышестоящему процессу по уже установленному соединению.

## ПРОГРАММНАЯ РЕАЛИЗАЦИЯ

Реализация сосредоточена в файле `lab1.c`. Основные функции:

- `bind_listen_port` — одна попытка `bind`+`listen` на заданном порту;
- `make_server_with_fallback` — перебор портов от `pid_to_port(pid)` при `EADDRINUSE`, иначе вывод ошибки и отказ;
- `publish_listen_port` — `setenv("LAB1_SRV_PORT", ...)` перед `fork` потомков;
- `port_for_connect` / `connect_to_parent` — чтение порта из окружения или запасной вариант по `getppid()`, затем подключение с повторными попытками при `ECONNREFUSED`;
- в `main` вызывается `unsetenv("LAB1_SRV_PORT")`, чтобы не использовать устаревшее значение из оболочки запуска;
- `read_full` / `write_full` — доставка сообщений фиксированного размера;
- `worker_main` — точка входа потомка после `fork`: соединение с родителем, приём задания, вызов рекурсивной обработки с отправкой результата;
- `sort_with_upstream` — рекурсивная сортировка с ветвлением процессов и обменом по сокетам; при достижении глубины — `local_sort_count_swaps`;
- `sort_root` — начальный уровень без «upstream»-отправки наружу (результат остаётся в массиве корня);
- в `main` — разбор аргументов `n` и `max_depth`, заполнение массива, замер времени, проверка монотонности и сравнение с `qsort`.

Ниже приведены ключевые фрагменты кода.

**Выбор порта и запуск сервера с запасным портом (перебор при `EADDRINUSE`):**

```c
static int make_server_with_fallback(pid_t owner, uint16_t *chosen_port) {
    uint16_t base = pid_to_port(owner);
    for (unsigned attempt = 0; attempt < MAX_PORT_FALLBACK; attempt++) {
        uint16_t port = (uint16_t)(base + (uint16_t)attempt);
        int fd = bind_listen_port(port);
        if (fd >= 0) {
            *chosen_port = port;
            if (attempt > 0)
                fprintf(stderr,
                        "предпочтительный порт %u занят, слушаем запасной %u (pid %jd)\n",
                        (unsigned)base, (unsigned)port, (intmax_t)owner);
            return fd;
        }
        if (errno != EADDRINUSE) {
            fprintf(stderr, "bind 127.0.0.1:%u (pid %jd): %s\n", (unsigned)port,
                    (intmax_t)owner, strerror(errno));
            return -1;
        }
    }
    fprintf(stderr,
            "не удалось занять порт: перебрано %u вариантов начиная с %u (pid %jd)\n",
            (unsigned)MAX_PORT_FALLBACK, (unsigned)base, (intmax_t)owner);
    return -1;
}
```

**Передача фактического порта потомкам через переменную окружения:**

```c
static void publish_listen_port(uint16_t port) {
    char buf[16];
    snprintf(buf, sizeof(buf), "%u", (unsigned)port);
    if (setenv(ENV_SRV_PORT, buf, 1) != 0)
        perror("setenv " ENV_SRV_PORT);
}
```

**Подключение потомка к родителю (порт из окружения или запасной вариант по PID):**

```c
static uint16_t port_for_connect(pid_t parent_pid) {
    const char *env = getenv(ENV_SRV_PORT);
    if (env && env[0]) {
        char *end = NULL;
        unsigned long v = strtoul(env, &end, 10);
        if (end != env && *end == '\0' && v > 0ul && v <= 65535ul)
            return (uint16_t)v;
    }
    return pid_to_port(parent_pid);
}
```

**Протокол обмена (родитель отправляет «глубина+1, n, массив», потомок читает и запускает обработку):**

```c
int32_t depth_next = 0, n = 0;
read_full(peer, &depth_next, sizeof(depth_next));
read_full(peer, &n, sizeof(n));
read_full(peer, buf, (size_t)n * sizeof(int32_t));
sort_with_upstream(peer, depth_next, buf, n);
```

**Локальная сортировка вставками с подсчётом «обменов» (сдвигов):**

```c
static int local_sort_count_swaps(int32_t *a, int n) {
    int swaps = 0;
    for (int i = 1; i < n; i++) {
        int32_t key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            swaps++;
            j--;
        }
        a[j + 1] = key;
    }
    return swaps;
}
```

Запуск: `./lab1 [размер_массива] [max_depth]` (по умолчанию 10000 и 3).

При `max_depth = 0` вся сортировка выполняется локально в корневом процессе без порождения дерева с сокетами (граничный случай). При `n = 1` корректно обрабатывается тривиальный массив. Если предпочтительный порт по PID занят, в stderr выводится сообщение о переходе на запасной порт; при этом проверки упорядоченности и совпадения с `qsort` остаются успешными.

## ЗАКЛЮЧЕНИЕ

Поставленная в `tz.txt` схема реализована: каждый родительский процесс принимает два локальных TCP-соединения от своих потомков, передаёт им подмассивы в формате «глубина+1, размер, данные», получает ответы «счётчик сдвигов, размер, данные» и объединяет результаты. Добавлен механизм запасных портов при занятости предпочтительного и передача фактического порта через `LAB1_SRV_PORT`, что снижает вероятность аварийного завершения из‑за `EADDRINUSE`. Программа успешно проходит проверки упорядоченности и совпадения с эталонной сортировкой `qsort`. Если подряд заняты все перебираемые порты (лимит задаётся константой в коде), привязка завершается ошибкой — такой случай маловероятен при обычной нагрузке на localhost.
