# Отчёт: лабораторная работа №3

## ВВЕДЕНИЕ

Многопроцессное программирование в UNIX позволяет распараллеливать вычисления за счёт создания независимых процессов с раздельными адресными пространствами. В отличие от потоков, процессы не разделяют память по умолчанию, поэтому для обмена данными используются механизмы межпроцессного взаимодействия. В данной работе реализована «быстрая» сортировка массива целых чисел с рекурсивным ветвлением процессов; передача подмассивов и возврат отсортированных результатов выполняется через неименованные каналы (pipe).

## ЦЕЛЬ РАБОТЫ

Освоить на практике создание дерева процессов (`fork`), синхронизацию через `wait`, работу с полудуплексными каналами `pipe`, переназначение дескрипторов `dup2` и обмен бинарными данными через `read`/`write` на примере рекурсивного алгоритма быстрой сортировки.

## ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ

**Процессы и `fork`.** Вызов `fork()` создаёт копию текущего процесса. Родитель получает PID потомка, потомок — ноль. Оба продолжают выполнение с одной и той же точки; открытые файловые дескрипторы копируются и указывают на те же открытые файлы (общий счётчик ссылок на объект в ядре).

**Неименованные каналы `pipe`.** Пара дескрипторов `[0]` — чтение, `[1]` — запись. Канал полудуплексный: данные идут в одну сторону; для двустороннего обмена создают два pipe или используют сокеты. Закрытие всех дескрипторов, связанных с записью, даёт читателю EOF.

**Быстрая сортировка.** Выбирается опорный элемент, массив разбивается на части «меньше опорного» и «не меньше опорного»; части сортируются рекурсивно, затем объединяются с учётом положения опорного.

**Дерево процессов.** Корневой процесс соответствует корню рекурсии; при каждом ветвлении создаются два потомка для левой и правой частей. Глубину ветвления ограничивают, чтобы не создавать чрезмерное число процессов и чтобы на «листьях» выполнялась локальная сортировка.

## ОПИСАНИЕ АЛГОРИТМА

**Опорный элемент.** Используется схема разбиения Ломуто: опорным берётся последний элемент подмассива; после разбиения он оказывается на окончательной позиции, слева — элементы строго меньше, справа — не меньше.

**Передача потомкам.** Для левого и правого подмассива создаются два канала «к потомку» и два «от потомка». Родитель записывает в pipe заголовок (число элементов) и сами `int`, закрывает конец на запись. Потомок читает данные, рекурсивно обрабатывает их (снова может породить пару процессов, если не достигнута максимальная глубина).

**Условие остановки рекурсии.** Если `depth >= max_depth` или разбиение вырождено (вся часть ушла в одну сторону от опорного), подмассив сортируется сортировкой вставками в текущем процессе без новых `fork`.

**Слияние результатов.** Потомки возвращают отсортированные левую и правую части и число `fork` в своём поддереве. Родитель собирает массив как: отсортированная левая часть, значение опорного, отсортированная правая часть — это корректно, так как все элементы слева меньше опорного, справа — не меньше.

## ПРОГРАММНАЯ РЕАЛИЗАЦИЯ

**Структура.** Функции `read_all`/`write_all` обеспечивают полные блоки чтения и записи; `write_sorted_chunk` передаёт наверх размер, счётчик `fork` в поддереве и массив; `partition_lomuto` выполняет разбиение; `parallel_qsort` — основная рекурсия с `pipe`, `fork`, `dup2`, `waitpid`; в `main` формируется массив (размер не меньше 11 по условию), вызывается сортировка, печатается результат и выполняется проверка.

**Ключевые моменты.** После `fork` каждый процесс закрывает неиспользуемые концы чужих pipe, чтобы не держать лишние ссылки и чтобы корректно сигнализировать EOF. В потомке `dup2` переносит чтение входного канала на `stdin` и запись выходного на `stdout` (как требует задание). Счётчик вызовов `fork` агрегируется вверх по дереву через pipe (у процессов нет общей памяти после `fork`).

## ТЕСТИРОВАНИЕ

**Сборка и запуск.**

```bash
gcc -std=c11 -Wall -Wextra -o quicksort_proc lab3.c
./quicksort_proc 20 3
```

**Пример вывода** (значения массива меняются из-за `rand()`):

- Параметры: 20 элементов, максимальная глубина ветвления процессов 3.
- Печатаются исходный и отсортированный массивы, строки «Проверка порядка: ОК», «Сравнение с qsort: ОК», суммарное число вызовов `fork()`.

**Проверка корректности.** После сортировки выполняется проход с проверкой неубывания и независимое сравнение с эталоном (`qsort` по копии массива).

**Количество процессов.** Каждый внутренний узел, в котором выполняются два успешных `fork`, добавляет к счётчику 2 плюс вклады от левого и правого поддеревьев. При полном бинарном дереве до глубины `d` (уровни ветвления 0…d−1) число вызовов `fork` растёт как сумма по уровням; при ограничении глубины и данных реальное число зависит от разбиений.

**Дополнительные прогоны:** `./quicksort_proc 11 0` (только локальная сортировка, 0 вызовов `fork`); увеличение размера и глубины для наблюдения роста числа процессов.

## ЗАКЛЮЧЕНИЕ

Реализована быстрая сортировка с передачей подмассивов через `pipe`, ограничением глубины рекурсии по процессам и сборкой результата в родителе. Основные сложности: аккуратное закрытие дескрипторов после `fork` (ошибочное закрытие конца канала до `dup2` приводит к «Bad file descriptor») и передача агрегированной статистики без разделяемой памяти. Pipe удобны для потоковой передачи данных по дереву, но для крупных массивов накладные расходы на копирование в канал велики; для учебной задачи с малым `n` и небольшой глубиной этого достаточно.
